# Screen reader test checklist

Use this checklist when you sit down with a student who uses a screen reader every day. Let them drive. Your job is to watch, listen and write down what happens. Each test should take a minute or two, and the whole session about 45 minutes.

**Before you start**

- Clear the app's data so the tutorial shows up: open the app in a private window, or clear the site's data in the browser settings.
- Keep the app's own speech **off** for every test, except section 7.
- Write down the device, operating system version, browser and screen reader version.
- Mark each row Pass, Problem (write what happened) or Not tried.

## How to start each screen reader

| Screen reader | Device | Start it | Move to the next item | Activate |
|---|---|---|---|---|
| VoiceOver | Mac, with Safari | Cmd + F5 | VO (Ctrl + Option) + Right Arrow | VO + Space |
| VoiceOver | iPhone, with Safari | Settings → Accessibility → VoiceOver | Swipe right | Double-tap |
| NVDA | Windows, with Chrome, Edge or Firefox | Ctrl + Alt + N | Tab, or Down Arrow in browse mode | Enter |
| TalkBack | Android, with Chrome | Settings → Accessibility → TalkBack | Swipe right | Double-tap |

On a computer, the board needs the screen reader's **focus mode** (NVDA) or arrow keys passed through to the page (VoiceOver usually does this inside a grid). NVDA normally switches to focus mode by itself when you Tab onto a square. Note whether it did.

## 1. First visit and tutorial

| # | Do this | Expect | Result |
|---|---|---|---|
| 1.1 | Open the app for the first time | You hear "How to use Touchpoint", the introduction and step 1. Nothing talks before you touch or press anything, apart from the screen reader itself | |
| 1.2 | Move through the page from the top | First: "Skip to main content", then "Skip to the chessboard" | |
| 1.3 | Find the headings list (VO: Rotor; NVDA: H or Insert + F7; TalkBack: reading controls set to Headings) | One "Touchpoint Chess" heading, then the tutorial heading | |
| 1.4 | Find the landmarks (VO: Rotor; NVDA: D; TalkBack: Landmarks) | Banner, Messages region, Main and Sections navigation | |
| 1.5 | Choose Next step, then do tutorial step 2: reach e4 on the board | Each square you move to is read once, as "e3, empty". When you reach e4 you hear "Correct, that is e4…" | |
| 1.6 | Step 3: pick up the e2 pawn, then drop it on e4 | "Picked up white pawn on e2. It can go to e3, e4." Then a move message ending with "Correct" | |
| 1.7 | Step 4: move the knight on the board instead of typing | You are told to type the move, and the knight goes back to g1 | |
| 1.8 | Step 4: type Nf3 in "Type a move or command" and press Enter | You hear it confirmed. With a braille display, check that the input works in its usual mode | |
| 1.9 | Steps 5 to 8: press B, L, M and P on the board | Each one gives its answer and "Correct" in **one** message, not two that cut each other off | |
| 1.10 | Step 9: turn on app speech, change the text size and turn on high contrast | Each control reads its name and state, and each change is confirmed | |
| 1.11 | Open "If the app's speech does not work" | It expands and reads as a list | |
| 1.12 | Go back to the start of the tutorial and choose Skip tutorial at any step | The tutorial closes and focus goes somewhere sensible. Write down where it went | |
| 1.13 | Reopen it with the How to use button at the top | It starts again at step 1 | |

## 2. Moving around the board

| # | Do this | Expect | Result |
|---|---|---|---|
| 2.1 | Tab onto the board | Read as a grid or table, then "e2, white pawn". The board is a single Tab stop | |
| 2.2 | Arrow keys in each direction, then Home and End | Square name and contents, read once each time. Bumping the edge says "Edge of the board" | |
| 2.3 | Touch: swipe or drag a finger across the board (phones) | Each square is read. Double-tap picks a piece up | |
| 2.4 | Press R, then F, on any square | The rank is read from left to right, the file from near to far | |
| 2.5 | Press A on e4 after a few moves | The attackers of e4 are listed | |
| 2.6 | Tab off the board, then Shift + Tab back | You return to the same square, not a8 | |

## 3. Playing a game

| # | Do this | Expect | Result |
|---|---|---|---|
| 3.1 | Play e4 with the board, then wait | Your move is read, then "Computer: Black …" with no long silence and nothing repeated | |
| 3.2 | Try an illegal move, such as the pawn on e4 to e6 | You are told it cannot go there, and where it can go | |
| 3.3 | Get yourself into check (type moves for both sides with a friend on this device) | "White is in check" is read once, and the king's square says "in check" | |
| 3.4 | Castle by typing O-O | "White castles on the king side" | |
| 3.5 | Promote a pawn | A question appears in the page, focus moves to it, and it reads "Promote your pawn". Choose Rook. Then try Escape to cancel | |
| 3.6 | Open Game options, then choose New game mid-game | A confirmation appears in the page with focus on it. "Keep playing" keeps the game. You can Tab away from it, so you are not trapped | |
| 3.7 | Choose Undo | The move is taken back and announced | |
| 3.8 | Reload the page | "Welcome back" appears and the game is still there | |

## 4. Lessons

| # | Do this | Expect | Result |
|---|---|---|---|
| 4.1 | Open the Learn tab | Focus moves to the "Learn" heading. Progress is read as words, such as "0 of 14 lessons finished" | |
| 4.2 | Lessons list | Read as a numbered list, and each button names its lesson, such as "Start here: The board map" | |
| 4.3 | Start The rook and make a wrong move | "Not quite…", the piece goes back, and you can try again | |
| 4.4 | Press H | A hint that says which piece to pick up and where it should go, and outlines the square | |
| 4.5 | Make the right move | Only the feedback is read ("Correct. … Rooks can travel…"), not the whole lesson card again | |
| 4.6 | Answer a question in Captures and piece values | Right and wrong answers are clear without relying on colour | |
| 4.7 | Finish a lesson, then go back to Learn | That lesson says "Done" and the progress count has gone up | |
| 4.8 | Work through Simple tactics | The fork, pin and skewer explanations make sense to the student | |

## 5. Settings

| # | Do this | Expect | Result |
|---|---|---|---|
| 5.1 | Open the Access tab and move through it | Group headings, then each control with its label and description | |
| 5.2 | Change a switch, a dropdown and a slider | Each reads its new state or value, such as "1.2 times normal speed" | |
| 5.3 | Choose the "I use a screen reader" quick setup | It is confirmed, and app speech stays off | |

## 6. Low vision (also useful without a screen reader)

| # | Do this | Expect | Result |
|---|---|---|---|
| 6.1 | Zoom the browser to 200%, then 400% | Nothing is cut off and the page does not scroll sideways (the board may) | |
| 6.2 | Try each text size, and high contrast in light and dark | Everything stays readable, and the focus ring is easy to see | |
| 6.3 | Turn on iOS or Android system large text, or Windows High Contrast | The board stays readable | |

## 7. The app's own speech

| # | Do this | Expect | Result |
|---|---|---|---|
| 7.1 | Screen reader **off**. Press the Speech button | "App speech is on…" in the device's voice | |
| 7.2 | Change the voice, speed and volume on the Access tab | A sample plays each time and the change is heard | |
| 7.3 | Play a move, then press P | The last message is spoken again | |
| 7.4 | During a long message, press X or the Stop button | Speech stops at once | |
| 7.5 | Close the tab and open the app again | App speech is off again until it is turned on | |
| 7.6 | Screen reader **on** and app speech **off** | The screen reader still reads every move and result | |

## Questions to ask the student afterwards

1. What was the hardest part to figure out?
2. Was anything read twice, cut off, or not read at all?
3. Did the tutorial help, and was it too long or too short?
4. Would you use this to practise between lessons on a real board? What would make you more likely to?
5. Did anything feel childish or too slow?
